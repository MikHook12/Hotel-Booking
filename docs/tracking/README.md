# Регламент Issues и GitHub Projects

## Задача

Каждая конечная задача содержит один основной кодИСР, конкретный результат, ответственного, условия приёмки, плановые часы, фактические часы, итерацию и ссылку на результат. SP назначаются истории, а не автоматически каждой подзадаче. Статус вProject не заменяет решение заказчика.

Статусы: **Сделать → В процессе → Сделано → Принято**. Возврат при замечании — в«Сделать» с причиной. WIP — одна активная задача на участника. Работа с кодом ведётся в репозитории реализации; в учебномIssue ставится ссылка на егоPR/commit.

## Поля Project

| Поле | Тип / значения |
| --- | --- |
| Status |Single select: Сделать, В процессе, Сделано, Принято |
| ИСР |Text:1.1–5.5 |
| Тип |Single select: Пакет, История, Задача, Дефект |
| Приоритет |Single select: Must, Should, Could, Won’t |
| Итерация |Iteration,14 дней; даты только после согласования |
| SP |Number, только для историй |
| План, ч / Факт, ч |Number; факт подтверждается журналом |
| Результат |Text/URL наcommit, документ или протокол |

Представления: Backlog(таблица по приоритету), Board(группировкаStatus), Iteration(текущая итерация), Team(Assignees), Roadmap(даты и вехи). Автоматизация закрытияIssue не должна подменять«Принято».

## Фактические часы

Факт вносится в день работы в [time-log.csv](../iterations/time-log.csv): дата,Issue, участник, одинИСР, часы, результат и ссылка. Не суммировать часы родительского пакета и его дочерних задач повторно. Назначения на GitHub-аккаунты выполняются после проверки соответствияФИО илогина.

Для созданияProject нужен владелец с доступом кProjects. Через подключённыйAPI в этой задаче создание и настройкаProject не доступны: регламент подготовлен, но существование настроенной доски не заявляется. До её настройки используется [рабочая таблица](https://docs.google.com/spreadsheets/d/1BISiz_b8gf3QQ-TnZRHUzSZgwgeg5OeqE3bZcr7_sb0/edit). После переноса выбрать один основной журнал факта, не вести две расходящиеся версии.


## Подготовленный набор Issues

[issues-ready.json](issues-ready.json) содержит59карточек:25пакетов,18историй и16задачI1. СозданиеIssues в данной сессии отклоненоGitHub с403; ни одна карточка не опубликована.

`python scripts/publish_issues.py` только выводит подготовленные данные. После проверки и получения доступа на запись владелец может выполнить `python scripts/publish_issues.py --apply`. Эта команда создаёт недостающиеIssues через установленный и авторизованныйGitHub CLI; повторный запуск пропускает совпадающие точные заголовки и сохраняет выданныеURL вissue-map.json. Assignees, даты иProject автоматически не выдумываются.

Пакеты являются сводным уровнем; фактические часы вносятся по конечным задачам. Перед массовой публикацией убрать или изменить задачи реализации, которые уже выполнены в существующемкоде.


## Перенос текущего состояния

В tracker-seed.csv два пакета сданных документов отмечены «Сделано». Для ИСР и репозитория отдельно описаны уже имеющиеся результаты: они не закрывают целиком базовый план и настройку трекера. Остальные открытые карточки описывают предстоящую проверку и доработку, а не утверждают отсутствие кода.

«План, ч» — значения исходного расчётного сценария. «Остаток, ч» и «Факт, ч» оставлены пустыми до получения достоверных данных. Не переносить 220 ч в остаточную трудоёмкость автоматически. Скрипт публикации создаёт открытые Issues; состояния Project переносятся из CSV отдельно.

Изменения этой редакции подготовлены в файлах. Публикация GitHub и актуализация прежней Google-таблицы в этой корректировке не выполнялись.
