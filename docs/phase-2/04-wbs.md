# Текстовое представление: 04_ИСР

Источник: [04_ИСР.docx](04_ИСР.docx). Текст извлечён из текущего файла репозитория; исходная версия и оформление сохраняются в DOCX.

Иерархическая структура работ

HotelReservationService • Группа 11 • Версия 1.1 • 19.10.2026

Три уровня: 0 — весь проект; 1–5 — группы результатов; 1.1–5.5 — 25 пакетов работ. Схема определяет содержание проекта; последовательность и сроки задаются отдельным базовым планом.

Принцип декомпозиции и границы пакетов

Декомпозиция смешанная: на втором уровне выделены управленческие, инфраструктурные и продуктовые результаты; на третьем — завершённые пакеты с проверяемым выходом. Соблюдается правило 100 процентов: охвачены разработка, среда, документы, демонстрационные данные, мониторинг и приёмка. Пользовательские истории и задачи раскрываются позднее внутри пакетов и не становятся дополнительными листовыми узлами этой ИСР.

Пакет 1.3 содержит создание и уточнение самой ИСР и базового плана. Пакет 1.4 содержит управление итерациями, а 5.5 — демонстрацию продукта и оформление результатов приёмки. Пакет 1.5 отвечает за управленческое закрытие после продуктовой приёмки. Пакет 2.3 описывает структуру данных, 5.3 — наполнение демонстрационными записями. Пакет 2.4 задаёт модель защиты, 3.1 реализует поведение учётных записей. Backend и UI учитываются отдельно; сквозная проверка относится к 5.2.

Прослеживаемость и контроль

П 1 → 2.5, 3.1–3.5, 4.1–4.5; П 2 → 2.2–2.4, 5.4; П 3 → 5.3; П 4 → 5.1, 5.2, 5.5; П 5 → 5.4; П 6 → 1.1–1.5, 2.1, 5.5. Каждая задача трекера и история бэклога содержит один основной код пакета; затраченные часы учитываются один раз. Идентификаторы сохраняются при перепланировании.

На фазе 3 каждый из 25 пакетов получает трёхточечную оценку, стоимость и предшественников. Суммарная трудоёмкость сверяется с 300 ч работы и 30 ч резерва из устава. В этой ИСР нет вымышленных оценок PERT: её назначение — зафиксировать полноту объёма и результаты для последующего оценивания.

Пакет завершён, когда указанный результат сохранён, проверен ответственным за качество и принят по применимому критерию устава. Статусы: «Сделать», «В процессе», «Сделано», «Принято». Решение заказчика фиксируется при приёмке; наличие файла само по себе не означает статус «Принято».

Распределение артефакта: Ушаков А. П. готовит схему, Колесник А. В. — словарь и проверку полноты; руководитель согласует. Полный состав команды указан в разделе 5 устава. Источники: «Задание.docx», фаза 2; Кутузов, раздел 2.6; исходники и README HotelReservationService.
