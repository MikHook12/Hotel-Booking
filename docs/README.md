# Документация проекта

Структура следует фазам практического задания. Нумерация фаз не равна порядку завершения работ. Публикация документа не означает его принятие заказчиком.

| Раздел | Содержимое |
| --- | --- |
| [Требования курса](requirements.md) | Матрица обязательных результатов и источники |
| [Текущий статус](STATUS.md) | Что установлено и что требует подтверждения |
| [Паспорт реализации](implementation.md) | Связь с исходным кодом и проверенной версией |
| [Фаза 1](phase-1/README.md) | Концепция из устава, требующая подтверждения заказчиком |
| [Фаза 2](phase-2/README.md) | Исходные DOCX/PNG и их текстовые представления |
| [Фаза 3](phase-3/README.md) | Предварительные расчёты и риски |
| [Фаза 4](phase-4/README.md) | Истории, бэклог, план I1, окружение |
| [Итерации](iterations/README.md) | Протоколы, отчёты, изменения и фактические часы |
| [Трекер](tracking/README.md) | Issues, поля GitHub Projects, статусы и учёт времени |
| [Решение по репозиториям](architecture/001-repositories.md) | Разделение управления и реализации |

Редактируемая управленческая документация хранится в Markdown/CSV; исходные файлы второй фазы сохранены. Ранее подготовленные расчёты помечены как сценарий до обследования реализации, чтобы не считать уже существующий код новой разработкой.


[Дополнение о прогрессе](phase-2/05-progress-addendum.md): первоначальная документация сдана, программная основа имеется; следующий этап — проверка и доработка.
