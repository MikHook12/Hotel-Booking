## Режимы API

Browser API v2 используется веб-интерфейсом с серверной сессией и CSRF. API v1 предназначен для отдельных REST-клиентов с HTTP Basic. Форматы запросов и способы авторизации этих версий различаются.

В browser API v2 публичная регистрация ограничена. Проверка US01 предусматривает вход в подготовленную учебную учётную запись и отдельную проверку регистрации в изолированном тестовом режиме. Итоговое решение по истории принимается по полному перечню её условий. Изменение сценария регистрации согласуется с заказчиком.

## Локальный стенд

Стенд запускается из репозитория реализации командой `node scripts/local.mjs start`. Эта команда соответствует вызову `./dev start`, описанному в README реализации. Требуются Docker Desktop, Java 21 и Node.js 22 или новее; зависимости интерфейса устанавливаются командой `npm ci` в каталоге frontend.

Команды `node scripts/local.mjs status` и `node scripts/local.mjs stop` используются для контроля и остановки. Начальное заполнение стенда содержит 3 учебных отеля и 6 комнат. Расширенный набор для итоговой проверки К9 формируется отдельной задачей.

## Контрольные команды

На Windows: `mvnw.cmd test` и `mvnw.cmd -Pintegration verify`. На других поддерживаемых системах: `./mvnw test` и `./mvnw -Pintegration verify`. Проверки интерфейса выполняются по frontend/README.md соответствующей версии.

Для протокола фиксируются версия кода, команда, окружение, результат, дата и ссылка на лог. Перечень файлов подтверждает состав реализации; прохождение сценария фиксируется отдельно в журнале проверок.
