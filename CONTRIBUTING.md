# Порядок работы команды

1. Перед работой открытьIssue сИСР, владельцем, результатом и критериями.
2. Создать ветку отmain; вmain изменения попадают черезPR с проверкой.
3. В документах использовать официальный русский язык, единые идентификаторы и ссылки. ИсходныеDOCX второй фазы не заменять без описания изменений.
4. Проверить `python scripts/validate_docs.py`. Эта команда проверяет документы, не приложение.
5. ВPR указать проблему, результат, связанныйIssue, выполненную проверку и оставшиеся ограничения. Ссылка наIssue описывает связь; она не даёт право отметить приёмку заказчиком.
6. Записать фактические часы по конечной задаче. Закрыть задачу после проверки результата; статус«Принято» — после отдельного решения заказчика.

Не хранить вGit пароли, токены, реальные персональные данные и локальные.env. Командные оценки, демо и подписи отражаются только по факту.
