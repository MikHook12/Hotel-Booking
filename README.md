# Регламент контроля проекта

## Основа расчёта

Расчётная стоимость работ BAC — 167 800 рублей, трудоёмкость — 220 часов. Управленческий резерв — 22 800 рублей и 30 часов; бюджет с резервом — 190 600 рублей. Резерв не включается в EV автоматически. Его использование оформляется изменением базового плана.

Таблица [control-units.csv](control-units.csv) распределяет бюджет каждого пакета ИСР между проверяемыми результатами. Сумма долей внутри пакета равна единице. Единица освоения получает 100 процентов стоимости после приёмки соответствующего результата; частичное начисление по количеству файлов не применяется. Распределение по итерациям согласуется в составе базового плана.

## Показатели

| Показатель | Расчёт | Интерпретация |
| --- | --- | --- |
| PV | Бюджет единиц, запланированных к отчётной границе | Плановая стоимость |
| EV | Бюджет принятых к отчётной границе единиц | Освоенный объём |
| AC | Сумма фактических часов, умноженных на ставки исполнителей | Фактическая расчётная стоимость труда |
| CV | EV - AC | Отрицательное значение означает перерасход |
| SV | EV - PV | Отрицательное значение означает отставание по объёму |
| CPI | EV / AC | Индекс исполнения стоимости |
| SPI | EV / PV | Индекс исполнения объёма относительно плана |
| EAC | AC + (BAC - EV) / CPI | Прогноз при сохранении эффективности стоимости |
| VAC | BAC - EAC | Прогноз отклонения итоговой стоимости |
| Velocity | Сумма согласованных SP историй, принятых в итерации | Наблюдаемая скорость команды |

SV выражается в стоимости, а не в календарных днях. При нулевом AC индекс CPI не определяется. При CPI, равном нулю, формула EAC не применяется. На ранней стадии допускается отдельный экспертный прогноз AC + ETC с обоснованной оценкой остатка. Отсутствие записи времени не трактуется как нулевые затраты.

## Журналы

| Реестр | Назначение |
| --- | --- |
| [control-units.csv](control-units.csv) | Распределение бюджета и приёмка единиц освоения |
| [rates.csv](rates.csv) | Условные ставки участников |
| [time-log.csv](time-log.csv) | Первичный учёт фактических часов |
| [story-acceptance.csv](story-acceptance.csv) | Решения по историям и согласованные SP |
| [change-log.csv](change-log.csv) | Запросы и решения по изменениям |
| [risk-log.csv](risk-log.csv) | Срабатывания, переоценки и меры |
| [defects.csv](defects.csv) | Замечания проверок |
| [retrospective.csv](retrospective.csv) | Приоритетное улучшение итерации |

Фазовые журналы проверок служат источником доказательств. Итоговое решение по истории переносится в общий реестр приёмки. Единственным первичным источником часов является time-log.csv.

## Расчёт отчёта

Для I1 используется report-I1.json, для I2 — report-I2.json. Указываются отчётная дата, дата согласования базового плана и признаки полноты фактического времени и приёмки. Команда: `python scripts/calculate_control.py --config docs/control/report-I1.json`.

До заполнения обязательных оснований выводится состояние «Ожидает отчётных данных». После заполнения выполняются проверки идентификаторов, бюджета, дат, ставок и полноты. Ошибочные записи блокируют расчёт. Учебные примеры проверки формул не записываются в журналы проекта.
