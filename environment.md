# Подготовка окружения

Используется отдельный локальный стенд репозитория HotelReservationService, версия `bbc0cff8a934ef6872ac008ef98a8eda5363f9e0`. Подготовка выполняется на учебных данных с сохранением конфигурации и результатов проверок.

## Последовательность подготовки

1. Получение исходного кода и фиксация версии.
2. Проверка Java 21, Node.js 22 или новее и Docker Desktop.
3. Установка frontend-зависимостей командой `npm ci` из каталога frontend.
4. Запуск из корня реализации: `node scripts/local.mjs start`.
5. Проверка состояния: `node scripts/local.mjs status`.
6. Выполнение модульных и интеграционных тестов по техническому паспорту.
7. Проверка входа, каталога и сохранения данных после штатного перезапуска.
8. Регистрация результата в [журнале окружения](environment-checks.csv).

## Условия демонстрации

Начальный локальный набор содержит 3 учебных отеля и 6 комнат. Для итоговой приёмки К9 используется расширенный набор, определённый уставом. Подготовленные учётные записи USER и ADMIN применяются раздельно.

Секреты находятся в закрытых локальных файлах .local и не включаются в отчёты. Публичная регистрация v2 ограничена; тест регистрации проводится в разрешённой изолированной среде. Порядок проверки US01 определён в [сценарии I1](../phase-5/demo.md).

## Контроль

Для каждого результата фиксируются дата, исполнитель, версия, команда, ожидаемое и фактическое поведение, ссылка на лог. Остановка выполняется командой `node scripts/local.mjs stop` с сохранением данных. Удаление томов не используется как способ устранения ошибок.
